Background / Theory Link

What this project is really testing这个项目真正要测试什么

Lecture 5 says the inverter is the real actuator. Coding Project 5 asks you to prove that claim in the repository code. You should be able to point to the exact variables where the controller's voltage request enters, where the dc-bus normalization appears, where sector logic is used, and where duty saturation limits what the inverter can really deliver. Lecture 5 强调：逆变器才是真正的执行器。Coding Project 5 要求你在仓库代码里把这件事证明出来。你应该能指出：控制器电压请求从哪个变量进入，母线归一化出现在哪一步，扇区逻辑在哪里，最终占空比饱和又是如何限制真实输出的。

Important scope范围提醒 Do not try to rebuild the whole FOC simulation from scratch. Your task is narrower and better defined: understand and validate the existing SVPWM path. 不要试图从零重建整个 FOC 仿真。你的任务应该更聚焦：理解并验证现有的 SVPWM 路径。

Experiments / Required Work

Required experiments必做实验

Experiment 1: Trace the signal path实验 1：追踪信号链

  1. Find where $u_{dq}^*$ becomes CTRL.cmd_uab.找出 $u_{dq}^*$ 变成 CTRL.cmd_uab 的位置。
  2. Record Ualfa, Ubeta, Ta, Tb, Tc.记录 Ualfa、Ubeta、Ta、Tb、Tc。
  3. Explain each variable physically.解释每个变量的物理意义。

Experiment 2: Observe detailed inverter behavior实验 2：观察详细逆变器行为

  1. Run once with MACHINE_SIMULATIONs_PER_SAMPLING_PERIOD = 1.先用 MACHINE_SIMULATIONs_PER_SAMPLING_PERIOD = 1 跑一次。
  2. Run again with a larger value such as 50, 100, or 500.再把它改成 50、100 或 500 再跑一次。
  3. Compare what “voltage command” means in these two modes.比较这两种模式下“电压命令”的实际含义差别。

Experiment 3: Build a simple SPWM comparison实验 3：做一个简化 SPWM 对照

  1. In your study copy, build a minimal SPWM-style phase-command normalization path.在你的副本里加一个最简 SPWM 风格的相电压归一路径。
  2. Keep the same dc bus and the same reference trajectory.保证母线和参考轨迹与 SVPWM 情况一致。
  3. Show which method saturates earlier.比较谁更早进入饱和。

Experiment 4: Sweep dc bus or command amplitude实验 4：扫母线电压或指令幅值

  1. Change DC_BUS_VOLTAGE or increase the voltage-reference amplitude.改变 DC_BUS_VOLTAGE，或逐步增大电压参考幅值。
  2. Observe duty clipping and tracking degradation.观察占空比贴边和跟踪恶化。
  3. Connect the result to the “constrained actuator” idea from Lecture 5.把结果和 Lecture 5 的“受限执行器”概念联系起来。

Analysis / Explain the Results

Questions your report must answer报告必须回答的问题

Q1

In the repository code, where does the controller-side voltage reference stop being “ideal” and start becoming “inverter realizable”?在仓库代码里，控制器侧的理想电压参考是从哪一步开始变成“逆变器可实现电压”的？

Q2

Why does adding a common zero-sequence term leave line voltages unchanged? Your answer should contain both algebra and physical interpretation.为什么加入一个共用零序项不会改变线电压？你的答案必须同时包含代数说明和物理解释。

Q3

What exactly causes SPWM to saturate earlier than SVPWM under the same dc bus?在相同母线下，SPWM 比 SVPWM 更早饱和的根本原因是什么？

Q4

Why does the current-loop output limit in the code use something proportional to DC_BUS_VOLTAGE / 1.732?为什么代码里的电流环输出限幅要用与 DC_BUS_VOLTAGE / 1.732 成比例的量？

Q5

What practical effect do duty-ratio clamps such as 0.96 and 0.04 have on the “ideal” modulation result?像 0.96 和 0.04 这样的占空比限制，会怎样改变“理想”调制结果？

Q6

When you enable detailed inverter simulation, what new gap appears between command and realization, and why is that gap educationally important?当你启用详细逆变器仿真时，“命令”和“实现”之间出现了什么新的差距？为什么这个差距在教学上很重要？

Strong reports do this好的报告会这样做 Do not only write “SVPWM uses the bus better.” Show exactly where the extra headroom appears in your comparison plots, and connect that observation to both the zero-sequence idea and the code-level normalization by 1/Vdc. 不要只写“SVPWM 更能利用母线”。要在图上明确指出多出来的余量体现在哪里，并把这个现象同时连接到零序注入思想和代码中的 1/Vdc 归一化。
